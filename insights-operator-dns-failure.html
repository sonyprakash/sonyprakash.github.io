Troubleshooting OpenShift Insights Operator: "lookup console.redhat.com ... server misbehaving"

Executive Summary
An OpenShift Insights Operator remained degraded because DNS resolution for console.redhat.com was failing from the node hosting the Insights pod. Rescheduling the pod to another control plane node resolved the issue.

Environment

  • OpenShift 4.14.38
  • Insights Operator

Symptom

Unable to report: unable to build request to connect to Insights server:

Post "https://console.redhat.com/api/ingress/v1/upload":

dial tcp: lookup console.redhat.com on 172.30.0.10:53:
server misbehaving

Investigation

The Insights Operator had been degraded for 38 days. The Insights pod was running on master-0. DNS resolution was tested from inside the pod. 

oc get co insights

oc get pod -n openshift-insights -o wide

oc debug node/master-0

dig @172.30.0.10 console.redhat.com

Result: 

status: REFUSED

Other control plane nodes were able to resolve the same domain successfully, indicating that the issue was isolated to the node hosting the Insights pod.

Root Cause

The node hosting the Insights pod was unable to perform DNS lookups through the cluster DNS service. As a result, the operator could not resolve console.redhat.com and failed to upload data to Red Hat Insights.

Resolution

The affected control plane node was cordoned and the Insights pod was restarted. 

oc adm cordon master-0

oc delete pod  -n openshift-insights

The pod was rescheduled to another control plane node and recovered successfully.

Verification

oc get co insights

Verify that the Insights Operator reports a healthy status and is no longer degraded.

Key Takeaways

  • Compare behavior across multiple control plane nodes.
  • Verify DNS resolution directly from the affected pod.
  • Operator issues may originate from node-specific problems.
  • Check DNS functionality before investigating the operator itself.
